# 마스터 대시보드: 기간 직접 지정 + 심각도 기반 정렬 설계

- 작성일: 2026-10-19
- 대상: 관리자 첫 화면(`index.html?admin=1`, "지점별 VOC 마스터 대시보드"), `reclassify.py` 재분류 단계
- 사용자 결정(2026-10-19): 심각도는 Claude가 리뷰별로 판정, 기간 특이사항은 키워드 자동 요약,
  **현재 UI 디자인은 유지**(새 디자인 요소를 만들지 않고 기존 컴포넌트·스타일 재사용).

## 1. 배경 / 문제

- 마스터 화면 기간은 1·3·6개월 프리셋뿐이고 날짜 직접 지정은 병원 상세 화면에만 있다.
- "주간 특이사항" 칸은 조회 기간과 무관하게 `weekly_notes.json`의 고정 7일 요약만 보여준다.
- 정렬(`buildSummaryRows`)이 `watch`(칭찬 리뷰 속 개선 요청)를 실제 부정 리뷰가 있지만
  부정 비율 10% 미만인 병원보다 위에 올린다. 긍정 리뷰뿐인 병원이 상단에 뜨는 원인이다.

## 2. 목표

1. 마스터 화면에서 시작일~종료일을 직접 지정할 수 있다(프리셋에 '최근 1주' 추가).
2. 리뷰 수·긍/부정 비율·키워드·특이사항·정렬이 모두 선택 기간 기준이다.
3. 심각한 부정 리뷰가 있는 병원이 맨 위, 그다음 일반 부정 리뷰가 있는 병원. 긍정뿐인 병원은 올라오지 않는다.

비목표: 유료 API, 화면 디자인 변경, 경쟁병원 화면 변경.

## 3. 데이터: 리뷰별 심각도(`severity`)

### 3.1 시트 컬럼
- `sheets_writer.HEADER` 맨 뒤에 `severity` 추가. 기존 `ensure_header`가 뒤에 붙은 컬럼을 자동으로 헤더에 추가한다.
- 값: 부정 리뷰에만 `심각` | `일반`. 긍정·중립·미판정은 빈 값.
- 수집 적재(`main.py`/`review_ingest`) 시점에는 빈 값.

### 3.2 재분류 작업(`reclassify.py`)
- `_tasks_for`에 `"severity"` 작업 추가:
  - `method == "lexicon"` 행 → `["sentiment", "key_points", "severity"]` (결과가 부정일 때만 severity를 적는다).
  - 이미 `부정`으로 확정되고 본문이 있으며 `severity`가 빈 행 → `"severity"` 포함(포인트도 비었으면 `key_points`도 함께).
  - 본문이 없는 부정 행(별점만) → `일반`으로 자동 기록하지 않고 후보에서 제외(추측 금지, 화면에서는 심각도 미판정=일반 취급).
- 결과 JSON: 후보 결과에 `"severity": "심각" | "일반"`. 다른 값이면 그 결과의 severity는 반영하지 않고 로그에 경고.
- 최종 감성이 부정이 아닌데 severity가 오면 무시.
- 기존 행 백필: 위 후보 규칙으로 이미 쌓인 부정 리뷰가 자동으로 후보가 되며, 매일 13:50 작업의 `--limit 300`·최대 4회 안에서 며칠에 걸쳐 채워진다. 자사 병원 우선, 경쟁병원은 기존처럼 최근 3개월만.
- `scheduled/daily_job.py`의 `claude -p` 프롬프트에 severity 작성 지시 한 줄 추가.

### 3.3 `심각` 판정 기준 (CLAUDE.md에 고정)
본문이 아래 중 하나를 **주장·언급**하면 `심각`:
- 시술·치료 후 부작용, 증상 악화, 재수술·재치료 필요
- 의료 과실·오진
- 환불·보상 요구, 법적 대응·신고(보건소·소비자원 등) 언급
- 폭언·모욕·차별적 응대
- 개인정보 유출·사진 무단 사용
- 강한 비난과 함께 방문하지 말라고 권함("절대 가지 마세요" 등)

그 밖의 불만(대기 시간, 가격, 주차, 예약 불편, 다소 불친절 등)은 `일반`. 애매하면 `일반`.

## 4. 화면(`index.html`, 디자인 유지)

### 4.1 기간 지정
- 마스터 화면 `#summaryRangeGroup` 옆에 병원 화면과 같은 날짜 입력(시작일·종료일·초기화)을 같은 마크업·클래스로 추가.
- 두 화면은 같은 `state`(mode/range/customStart/customEnd)를 공유한다. 한쪽에서 바꾸면 다른 쪽도 같은 기간.
- 프리셋 버튼 '최근 1주' 추가(두 화면 모두). `state.range`가 월 단위이므로 주 단위를 표현하도록 `currentWindowBounds`/`rangeLabel`/`priorWindowBounds`를 확장한다(예: `data-range="w1"` → 오늘 포함 7일).

### 4.2 정렬 (`buildSummaryRows`)
기간 내 리뷰로 계산:
1. `severeCount`(심각 부정 수) 내림차순 — 1건 이상이면 '리스크' 칩(기존 `.risk-chip.risk`).
2. `neg`(부정 수) 내림차순 → 부정 비율 내림차순 — 부정 1건 이상이면 '부정' 칩(기존 `.risk-chip.watch` 스타일 재사용, 문구만 '부정').
3. 부정 0건 → 긍정 비율 오름차순 → 리뷰 수 내림차순. 칩 없음.

`watch` 플래그·부정 급증·부정 비율 10% 규칙은 정렬·칩에서 제거한다. KPI '관리 지점' 보조 문구는 "리스크 N곳 · 부정 N곳"으로 바꾼다. 필터 `flagged`는 "리스크·부정 있음"으로 같은 의미 유지.

### 4.3 특이사항 칸 (기간 자동 요약)
기존 '주간 특이사항' 칸 자리 그대로, 헤더 문구만 '기간 특이사항'으로 바꾼다. 내용(기간 내 리뷰로 계산):
- `심각 N건(포인트1, 포인트2)` — 심각 리뷰의 key_points. 누르면 그 행 아래에 심각 리뷰 원문(날짜·채널·본문)이 펼쳐진다(기존 `<details>` 등 기본 요소, 새 스타일 최소화).
- `부정 N건: 포인트 a 2, b 1` — 일반 부정의 key_points 집계(상위 3개).
- `칭찬: x, y` — 긍정 key_points 상위 2개(`-` 제외).
- 기간 리뷰 0건 → "기간 내 리뷰 없음(마지막 리뷰 M월 D일)", 수집 리뷰 자체가 없으면 "수집된 리뷰 없음".
- 포인트가 비어 있는 리뷰(아직 재분류 전)는 건수에만 포함하고 포인트에는 넣지 않는다.
- `weekly_notes.json`의 문장: `period_start~period_end`가 선택 기간 안에 완전히 들어갈 때만 자동 요약 아래 작은 회색 글씨로 "주간 요약(MM/DD~MM/DD): …" 표시. 매주 작성 절차는 그대로 유지.

### 4.4 CSV 파싱
`toReview`에 `severity` 필드 추가(없거나 빈 값이면 `""`). 옛 시트(컬럼 없음)에서도 동작.

## 5. 오류·예외
- `severity` 컬럼이 아직 없거나 미판정: 해당 부정 리뷰는 '일반'으로 집계(심각으로 추정하지 않음). 화면 각주에 "심각도 미판정 부정 리뷰는 일반으로 집계" 명시.
- 시작일 > 종료일: 기존 병원 화면 검증 로직 재사용(반영하지 않음).
